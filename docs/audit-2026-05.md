## Drift findings

### D1 · `REQUIRED_PIECES` — gym entry (book S3 wrong)

The Part-II chapter [`book/S3-occasion-and-context.md`](../book/S3-occasion-and-context.md)
prints the table as pseudocode:

```python
REQUIRED_PIECES = {
    "work":    {"top", "bottom"},
    "gym":     {"top", "bottom"},        # activewear-tagged   ← wrong
    "dinner":  {"top", "bottom"},
    "formal":  {"dress"},
    "casual":  {"top", "bottom"},
}
```

The actual code (`styling_agent.py:63–69`):

```python
REQUIRED_PIECES = {
    "work":   ["top", "bottom"],
    "dinner": ["top", "bottom"],
    "gym":    ["activewear", "activewear"],   ← code reality
    "formal": ["dress"],
    "casual": ["top", "bottom"]
}
```

The code treats *gym* as needing two **activewear** pieces, not a
generic top+bottom. The book's pseudocode flattens that to top/bottom
with a comment, which is wrong.

**Action:** book wrong; fix S3 pseudocode and the explanatory
sentence.

### D2 · Step 6 label (book Ch 03 wrong)

`book/03-agent-workflow.md` line 27 prints:

```
6. Check Wardrobe Gaps       ← detect missing required pieces
```

The agent emits *"Check **for** Wardrobe Gaps"* at
`styling_agent.py:1144` (`step6 = {"step": 6, "name": "Check for
Wardrobe Gaps", …}`). One missing word.

**Action:** book wrong; add *"for"*.

### D3 · Forbidden-token list (book S8 wrong)

Book S8 lists 8 tokens:

> *flaw, fix, hide, minimize, correct, problem area, slimming,
> shameful*

`fit_tool.FORBIDDEN_TOKENS` actually contains **17 entries** across
**more root concepts**:

```python
FORBIDDEN_TOKENS = {
    "flaw", "flaws",
    "fix",
    "hide",
    "minimize", "minimise",
    "correct",  "corrective",
    "problem area", "problem-area", "problem_area", "problem zone",   ← extra concept
    "trouble area", "trouble-area",                                    ← extra concept
    "slimming", "slimmer",
    "shameful",
}
```

The book's S8 chapter discusses the *8 root concepts* but doesn't
acknowledge that the code enforces **two additional concepts**
("trouble area," "problem zone") and several variant spellings
(*minimise, slimmer, corrective, flaws*).

**Action:** book wrong; update S8 to either (a) reflect the full
list, or (b) note that the runtime list extends beyond the 8 root
concepts with additional families + spelling variants.

## Improvement target (not a drift)

### C10 · Live Reasoning Graph in the app

`graph_tool.py` (the pyvis renderer that powers the live-run graph
inside Streamlit) is mature: per-entity styles, semantic node-size
encoding (wear count, outfit-piece count), curved edges, body-positive
hover tooltips, an explicit `LEGEND_DICT` documented in code.

What it lacks, compared to the recently-improved
`docs/sims/learning-graph/main.html`:

1. **Force-directed layout by default.** McCreary's pattern is that a
   provenance graph should open hierarchical (top-down) so the
   User → Event → Outfit → Items chain reads at a glance. Wearly's
   live graph currently opens in `forceAtlas2Based` and lets physics
   converge, which makes the first frame look like a blob.
2. **No back-link to the abstract schema.** A first-time viewer of
   the live graph has no path to *"this is one instance of a
   well-defined schema — here's the schema."*

These aren't drift; they're upgrades that bring the app's runtime
graph to parity with the book's interactive Learning Graph.
